Effective Java 3Ed. item66.

아이템 66. 네이티브 메서드는 신중히 사용하라

- 자바 네이티브 메서드란?

  • native 키워드를 사용하여, java 가 아닌 C, C++ 같은 다른 프로그래밍언어(네이티브코드) 로 구현된 함수를 java 코드에서 직접 호출하는 메서드.

- 목적

  1. 레지스트리등 플랫폼 특화기술
    Java -> JNI -> OS API (Win32 API, POSIX) -> 하드웨어/커널
  2. 레거시 C, C++ 라이브러리 활용
  3. 성능 크리티컬한 부분을 C로 최적화 (요즘엔 vm 성능이 극적으로 향상되어, 유명무실.)

- 단점

  1. 메모리 안전성 파괴
  2. 플랫폼 독립성 상실
  3. 디버깅 난이도 급상승
  4. GC와의 상호 작용 복잡성

- 대안

  1. Panama API로 JNI 완전 대체
  2. 성능 측정후 결정하는 원칙
  3. GraalVM Native Image로 네이티브 필요성 제거

- JNI는 Java의 안전망에 구멍을 뚫는다. 현대 Java는 그 구멍을 하나씩 메우고 있다.

Effective Java 3Ed. item65.

아이템 65. 리플렉션보다는 인터페이스를 사용하라

- 리플렉션이란? java.lang.reflection

  • 프로그램이 자기자신의 구조를 런타임에 조사하고 조작하는 기능

- 리플렉션의 단점

  1. 컴파일 시점에 타입 검사 불가
  1. 장황하고 복잡한 코드: Exception만 붙여도 6종.
    ClassNotFoundException NoSuchMethodException IllegalAccessException
    InstantiationException InvocationTargetException ClassCastException …
  2. 성능저하 - 아래 과정을 매번 거침.
    invoke() 호출 -> 접근권한 검사(isAccessible?) -> 파라미터 타입 검증
    -> 오토박싱 (primitive -> Object) -> 실제 메서드 디스패치 -> 결과 언박싱

- 리플렉션의 활용

  • 컴파일시에는 알수 없고, 런타임에 존재하지 않을수도 있는 다른 클래스, 메서드의 의존성 판단시
  • 버전이 여러개인 외부 클래스의 의존성 선택.

- 대안

  • 생성만 리플렉션, 생성 이후에 사용할때는 인터페이스나 상위클래스로 형변환해서 사용.
  • 참고!! 코드65-1 참조할것. 제너릭 Set 성능 분석 도구로 활용할 수 있음.

Effective Java 3Ed. item64.

아이템 64. 객체는 인터페이스를 사용해 참조하라

- 구현 클래스 타입이 아닌 인터페이스 타입으로 변수를 선언하라.

  • 다형성에 기반한 교체 유연성 도모

- 구현 클래스타입으로 선언하면, 그 클래스가 가진 불필요한 메서드 까지 노출됨.

  • 추후 인터페이스 타입으로 변경하려고 해도, 의존 코드를 다시 검토해야함.

- 예외. 인터페이스가 없는 클래스

  • 값 클래스: String, BigInteger
  • 인터페이스 없는 클래스 기반 프레임워크: 그래도, 구현클래스 보다는 추상클래스로 선언할것. java.io.OutputStream
  • 인터페이스에 없는 메서드가 필요한 경우: 구현클래스의 고유기능이 필요한 경우.
  • 요점. 가급적 덜 구체화된 클래스를 사용하여 선언하라.

Effective Java 3Ed. item61.

아이템 61. 박싱된 기본 타입보다는 기본 타입을 사용하라

- 기본타입 Primitive type 에 대응되는 Reference type 이 Boxing된 기본타입.(래퍼클래스)

  • int -> Integer, double -> Double, boolean -> Boolean

- 주된 차이점 3가지

  • 기본타입은 값만 있으나, 박싱된 타입은 값과 identity가 있다. 코드61-1
    I < J 값 비교시 정상작동, I == J 값 비교시 false

  • 기본타입은 언제나 값이 있다. 박싱된 기본타임은 null 을 가질 수 있다. 코드61-3
    초기화 안된 박싱타입을 기본타입과 연산시 언박싱 되면서 NullPointerException 발생.

  • 기본타입이 박싱된 타입보다 메모리 면에서 효율적이다. 코드61-4
    for 문에 기본타입과 박싱 타입 혼용시 언박싱이 계속 발생하며 느려짐

박싱된 기본타입은 언제 사용하나

  • 컬렉션의 원소, 키, 값 으로 사용 <제너릭>

Effective Java 3Ed. item60.

아이템 60. 정확한 답이 필요하다면 float와 double은 피하라

- float, double의 특징

  • 과학과 공학 계산용으로 설계
  • 이진 부동소수점 연산에 사용
  • 넓은 범위의 수를 빠르게 정밀한 근사치로 계산하도록 설계
  • 따라서, 정확한 결과가 필요할 때에는 사용하면 안된다 (의외네)
  • 특히, 금융관련 계산에서 사용하지 말것.

- 대안은 BigDecimal, int 혹은 long 이다.

  • 작은 수엔 int(9자리), long(18자리) 사용. 큰수는 BigDecimal(18자리 이상)을 사용하라.
  • BigDecimal 이 제공하는 8가지 반올림 모드가 있어 완벽히 제어 [??]

- 그러나, BigDecimal의 단점 두가지

  • 기본타입보다 사용이 불편하다

Effective Java 3Ed. item59.

아이템 59. 라이브러리를 익히고 사용하라

- 예시에서는 Random 클래스를 활용한 난수 생성 메소드를 구현하고 그것을 사용하는데 있어, 몇가지 문제가 발생함을 경고한다.

  • 같은 수열이 반복되거나,
  • 몇몇 숫자가 자주 등장하거나,
  • 확률상 수의 분포가 고르지 않거나 이다.

단순히 Random() 함수 사용을 경고하는게 아니라, 가급적 많은 문제를 선도적으로 해결한 라이브러리를 사용할 것을 권장함.

  • ThreadLocalRandom 을 사용하여, 속도도 빠르고 더 랜덤한 값을 얻는다.

- 아래의 이유로 라이브러리 사용을 권장한다.

  • 시간을 허비하지 말자. 잘 만들어진 라이브라리를 잘 찾아서 사용하고, 기능개발에 집중해라.
  • 라이브러리는 지속적으로 성능이 개선된다.
  • 심지어 기능이 점점 많아지기도 한다.
  • 내 코드가 다른 이들에게 더 낮익고 익숙한 코드가 된다.

- 최소한 아래의 JAVA의 패키지들은 익숙해져라

  • java.lang
  • java.util
  • java.io
  • java.util.concurrent item80, item81

- java 고유 라이브러리에 익숙해지고, 없다면 third-party 라이브러리에도 관심 가져라 Guava 등등..
