  • 오픈소스 + 모델 프로바이더 비종속 (75+ LLM 지원)

7. Henry 현재 스택에 대한 기술적 평가

강점

  • 모델 비종속성: 작업 유형별 최적 모델 라우팅 (Claude Opus → 추론, Gemini → 프론트엔드, 로컬 Qwen → 유틸리티)
  • 병렬 실행: Sisyphus 오케스트레이터가 연구/구현/검증을 동시 진행
  • LSP + AST: IDE 수준의 리팩터링 (rename, find-references, pre-build diagnostics)
  • Hash-anchored edit: 라인 번호 불일치 편집 오류 방지
  • 비용 최적화 가능: 로컬 모델(Ollama)로 유틸리티 에이전트 운영

리스크 / 주의사항

  • 빌링 버그 (이슈 #2571): 2026.03 $438 단일 오후 청구 사례 → circuit breaker 설정 필수
  • Hello World 토큰 오버헤드: 단순 작업에도 15,000~25,000 토큰 초기화 비용
  • OpenCode 버전 종속성: OpenCode 1.1.37+ 이후 일부 기능 자동 비활성화
  • Anthropic 정책: OAuth 토큰 차단(2026.01) → API key 방식만 사용 가능

8. 결론 및 추천 구성

Henry의 PL/SQL 데이터 마이그레이션 프로젝트 기준 최적 조합

최종 권고

현재 스택(OpenCode + OmO)은 2026년 기준 md 기반 멀티에이전트 개발에서
가장 유연하고 비용 효율적인 오픈소스 선택지임.
단, 빌링 안전장치(circuit breaker, step limit) 설정을 최우선으로 적용할 것.

시장 조사 결과 요약
Henry의 현재 스택인 OpenCode + oh-my-openagent가 이 분야에서 상당히 앞선 선택이라는 게 조사 결과의 핵심입니다. 구체적으로 설명하면:

🔍 Henry 스택의 배경 (업계 맥락)
oh-my-openagent(이전 명칭 oh-my-opencode)는 한국 개발자 김연규(@code-yeongyu)가 제작한 프로젝트로, OpenCode 위에서 멀티에이전트 오케스트레이션을 구현합니다. Anthropic이 2026년 1월 OpenCode의 OAuth 토큰 접근을 공식 차단했음에도, 팀은 GPT 기반 독립 에이전트(Hephaestus)를 구축하는 것으로 대응했습니다. Jeongil
2026년 4월 기준 OmO는 GitHub 48,000+ 스타, 다운로드 1.6M+를 기록하며, 3계층 아키텍처(Planning → Orchestration → Execution)와 모델별 프롬프트 튜닝, 40+ 라이프사이클 훅을 갖춘 멀티에이전트 시스템으로 성장했습니다. a2a mcp

📊 주요 경쟁/대안 스택
① Claude Code Agent Teams (공식)
Claude Code의 Agent Teams는 16개 이상의 Claude 인스턴스를 병렬로 실행하고 공유 태스크 리스트로 조율합니다. 한 사례에서는 16개 에이전트가 자율적으로 10만 라인의 Rust C 컴파일러를 구축했습니다. 단, Claude 모델만 사용 가능하며 Agent Teams는 아직 실험적(Research Preview) 상태입니다. Nxcode
② OpenAI Codex CLI
Codex CLI는 GitHub 통합이 강력하며, @Codex를 GitHub 이슈/PR에서 직접 멘션하면 자율적으로 픽업하여 작업합니다. Agents.md 파일 포맷을 표준으로 채택하고 있어 Cursor, Builder.io 등 타 도구와도 호환됩니다. Builder.io
③ CrewAI (프레임워크 레이어)
CrewAI는 멀티에이전트 오케스트레이션에 특화된 오픈소스 프레임워크로, researcher/planner/reviewer 같은 역할 기반 에이전트 팀을 Python 코드로 구성합니다. 자체 호스팅이 가능하며 코드베이스를 직접 제어할 수 있습니다. Gumloop

⚠️ 현재 스택의 핵심 리스크 (반드시 체크)
2026년 3월 이슈 #2571에서 확인된 빌링 버그: 서브에이전트 스텝 한도 없음 + 루프 감지 실패 + 지연된 비용 알림의 3중 오류가 겹쳐 한 사용자에게 단 오후 한나절에 $438가 청구됐습니다. 수정이 진행 중이나 아직 배포되지 않았습니다. The4thpath
또한 “Hello world” 메시지 하나에도 컨텍스트 초기화만으로 15,000~25,000 토큰이 소비됩니다. ultrawork 모드를 단순한 작업에 쓰면 낭비가 심합니다. The4thpath

🏁 2026년 개발자 커뮤니티의 실제 패턴
경험 많은 개발자들 사이에서 가장 일반적인 패턴은 80/15/5 법칙입니다: 시간의 80%는 Cursor/Windsurf의 자동완성과 인라인 편집, 15%는 중간 복잡도 에이전트 작업, 그리고 5%만 Claude Code 같은 복잡한 멀티파일 작업에 씁니다. 그 5%가 처리하는 작업이 수 시간짜리 수동 작업을 대체하기 때문에 ROI는 불균형적으로 높습니다. DEV Community
