아이템 15. 클래스와 멤버의 접근 권한을 최소화하라

1. 핵심 원칙: 정보 은닉 (캡슐화)

잘 설계된 컴포넌트는 모든 내부 구현을 완벽히 숨기고, 외부와는 오직 API를 통해서만 소통합니다.
이를 정보 은닉(information hiding) 또는 **캡슐화(encapsulation)**라고 합니다.

정보 은닉이 중요한 이유:

  • 시스템 개발 속도 향상 — 여러 컴포넌트를 병렬로 개발할 수 있다.
  • 시스템 관리 비용 절감 — 컴포넌트를 빠르게 파악하고, 교체 부담이 줄어든다.
  • 성능 최적화에 도움 — 다른 컴포넌트에 영향 없이 특정 컴포넌트만 최적화할 수 있다.
  • 소프트웨어 재사용성 증가 — 독립적으로 동작하는 컴포넌트는 낯선 환경에서도 유용하다.
  • 큰 시스템 개발의 위험 감소 — 개별 컴포넌트 단위로 검증 가능하다.

원칙: 모든 클래스와 멤버의 접근성을 가능한 한 좁혀라.

2. 자바의 접근 제어 메커니즘

자바는 클래스, 인터페이스, 멤버의 접근성을 **접근 제한자(access modifier)**로 제어합니다.

접근 제한자는 private, package-private(기본값), protected, public 네 가지입니다.

접근 제한자 같은 클래스 같은 패키지 하위 클래스 어디서나
private O X X X
package-private (기본값) O O X X
protected O O O X
public O O O O

3. 클래스 수준의 접근 제한

톱레벨(top-level) 클래스와 인터페이스는 public 또는 package-private 두 가지만 가능합니다.

package-private으로 선언하면 좋은 경우

패키지 외부에서 쓸 일이 없다면, package-private으로 선언하세요.
그러면 API가 아닌 내부 구현이 되므로, 언제든 수정·교체·삭제할 수 있습니다.
반면 public으로 선언하면 하위 호환을 영원히 유지해야 합니다.

private static 중첩 클래스 활용

한 클래스에서만 쓰이는 톱레벨 클래스라면, 사용하는 클래스 안에 private static 중첩 클래스로 선언하세요.

4. 멤버(필드, 메서드, 중첩 클래스) 수준의 접근 제한

기본 원칙

  • 먼저 클래스의 공개 API를 신중히 설계하고,
  • 그 외 모든 멤버는 private으로 선언한다.
  • 같은 패키지 내 다른 클래스에서 꼭 필요한 경우에만 package-private으로 풀어준다.
  • protected와 public은 공개 API가 되므로 영원히 지원해야 한다.

private과 package-private은 내부 구현이라 공개 API에 영향을 주지 않습니다.
단, Serializable을 구현한 클래스는 의도치 않게 노출될 수 있습니다.

리스코프 치환 원칙과 접근 수준

상위 클래스 메서드를 재정의할 때, 접근 수준을 더 좁게 만들 수 없습니다.

인터페이스를 구현하는 클래스의 메서드는 반드시 public이어야 합니다.
(인터페이스 메서드는 기본적으로 public이기 때문)

5. public 클래스의 인스턴스 필드

public 클래스의 인스턴스 필드는 가급적 public이어서는 안 됩니다.

public 가변 필드를 갖게 되면:

  • 필드에 저장될 값을 제한할 수 없다 (불변식 보장 불가).
  • 필드 변경 시 다른 작업을 수행할 수 없다 (스레드 안전 확보 불가).

6. public static final 필드의 주의사항

상수라면 public static final 필드는 허용됩니다.
단, 반드시 기본 타입 값이나 불변 객체를 가리켜야 합니다.

public static final로 선언해도 배열의 내용은 외부에서 바꿀 수 있습니다.

7. Java 9의 모듈 시스템 (참고)

Java 9부터 모듈(module) 개념이 추가되었습니다.
모듈은 패키지의 묶음이며, 자신이 공개할 패키지를 module-info.java에 명시적으로 선언합니다.

  • public 클래스라도 해당 패키지가 모듈에서 공개되지 않으면 외부에서 접근 불가.
  • 모듈 내부 패키지끼리는 공유할 수 있지만, 외부 모듈에는 숨길 수 있다.

단, 모듈 시스템의 이 추가 접근 수준은 모듈 경로에 배치된 경우에만 적용됩니다.
일반 클래스패스에 놓이면 모듈 선언이 무시됩니다.

8. 핵심 정리

  • 접근성은 항상 최소화하라. 의도치 않게 API를 공개하지 않도록 주의하라.
  • public 클래스는 상수(public static final) 외에는 공개 필드를 가져서는 안 된다.
  • public static final 필드가 참조하는 객체는 반드시 불변이어야 한다.
  • 배열은 public static final로 두어서는 안 된다. 불변 리스트나 방어적 복사를 활용하라.
