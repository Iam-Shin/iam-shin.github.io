아이템 14. Comparable을 구현할지 고려하라

책을 다시 읽고 다시 이해해라 !!

  • 아래 내용은 Claude가 요약한 내용.

1. Comparable 인터페이스란?

Comparable 인터페이스는 compareTo 메서드 하나만 가진 인터페이스입니다.

equals와 달리, compareTo는 순서 비교를 합니다. 즉, “나는 저 객체보다 크냐, 같냐, 작냐”를 판단합니다.

2. 왜 구현해야 하나?

Comparable을 구현하면 그 클래스의 인스턴스에 **자연적인 순서(natural order)**가 생깁니다.
자바 플랫폼의 거의 모든 값 클래스(String, Integer, BigDecimal 등)와 열거 타입이 이미 구현하고 있습니다.

구현하면 이런 것들이 자동으로 됩니다:

순서가 있는 값 클래스를 만들 때는 반드시 Comparable을 구현하세요.

3. compareTo의 일반 규약

compareTo는 세 가지 규약을 지켜야 합니다.
(sgn()은 부호 함수 — 음수면 -1, 0이면 0, 양수면 1)

규약 1. 대칭성

  • x가 y보다 크면, y는 x보다 작아야 한다.
  • x가 y에게 예외를 던지면, y도 x에게 예외를 던져야 한다.

규약 2. 추이성

  • x > y이고 y > z이면, x > z여야 한다.

규약 3. 일관성

  • x와 y가 같다고 판단되면, 다른 객체 z와의 비교 결과도 같아야 한다.

권고사항 (강제 아님)

  • compareTo가 0을 반환하면 equals도 true를 반환하는 것이 좋습니다.
  • 지키지 않으면 동작은 하지만, 컬렉션에서 이상하게 동작할 수 있습니다.

compareTo와 equals 불일치 예시 (BigDecimal)

4. compareTo 구현 방법

기본 원칙

상황 반환값
this < other 음수
this == other 0
this > other 양수

핵심: <, >같은 관계 연산자를 쓰지 마라

예전 코드처럼 직접 비교하면 정수 오버플로우 버그가 생길 수 있습니다.

올바른 방법 1: 박싱 타입의 정적 compare 사용

  • 중요도 순서대로 비교한다.
  • 앞 필드가 이미 다르면 바로 반환한다.

올바른 방법 2: Comparator 생성 메서드 활용 (Java 8+)

Java 8부터는 Comparator 인터페이스의 메서드 체이닝으로 우아하게 작성할 수 있습니다.

  • 코드가 간결하고 읽기 쉽습니다.
  • 단, 성능은 약 10% 정도 느릴 수 있습니다.

비교자 생성 메서드 종류

메서드 설명
comparingInt int 기준 비교
comparingLong long 기준 비교
comparingDouble double 기준 비교
comparing 객체 기준 비교
thenComparingInt 추가 int 기준 비교
thenComparing 추가 객체 기준 비교

5. extends vs implements의 규약 문제

compareTo 규약도 equals처럼 상속과 함께 쓰면 문제가 생깁니다.

새 필드를 추가한 서브클래스에서 규약을 지키면서 compareTo를 구현하는 것은 불가능합니다.
해결책은 **컴포지션(조합)**을 사용하는 것입니다.

6. 핵심 정리

  • 순서가 있는 값 클래스라면 반드시 Comparable을 구현하자.
  • compareTo에서 필드 비교 시 <, > 연산자 대신 Integer.compare() 같은 정적 메서드나 Comparator 생성 메서드를 사용하자.
  • compareTo와 equals가 일관되게 동작하도록 노력하자. (특히 TreeSet, TreeMap 등에서 중요)
  • 다중 필드 비교 시에는 가장 중요한 필드부터 비교하자.
