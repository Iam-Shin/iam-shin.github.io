Effective Java 3Ed. item12.

아이템 12. toString을 항상 재정의하라

- Object 의 기본 toString은 단순히 클래스명@16진수해시코드 형태다.

  • 읽기 쉽고 유용한 정보를 보여주도록 재정의 하자
  • phoneNUmber라면 ‘phoneNumber: Henry=010-1234-5678’

- Collection 또는 정보량이 많을경우 Summary 를 보여주는것도 좋다

  • “맨해튼 전화번호부 (총 2299000개)

- 중요한 정보는 충분히 담아라.

  • 잘못된 예: “단언실패 : 기대값 {abc, 123}, 결과값 {abc, 123}”
  • toString 메세지를 보고 혼란 유발. (클래스타입을 추가하거나, 인스턴스 해시코드를 추가해야하지 않을까)

- 포멧을 명시하든 아니든, 그 의도를 명확히 밝혀라.

- toString이 반환한 값에 포함된 정보를 얻어올 수 있는 API 를 제공하라

  • toString의 반환값을 파싱해야 값을 얻을수 있는 상황을 만들지 말라
  • phoneNumber 라면 getAreaCode, getPrefix, getMemberNUmber 같은 접근자를 제공하자.

- 하위 컬랙션이 공유해야할 문자열 표현이 있는 추상클래스라면 toString을 재정의 해줘라.
