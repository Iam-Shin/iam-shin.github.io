HEXO활용_3 git배포

✦ Hexo 블로그를 GitHub Pages(username.github.io)에 배포하는 방법은 크게 두 가지 저장소 관리 방식으로 나뉩니다.

배포 원리와 관리해야 할 파일들을 먼저 설명해 드릴게요.

  1. 배포의 핵심 원리
    Hexo는 ‘정적 사이트 생성기’입니다. 사용자가 작성한 .md(마크다운) 파일들을 실행 가능한 .html, .css, .js 파일로 변환하여 public 폴더에 생성합니다.
    실제 GitHub Pages에 올라가서 웹사이트로 보여지는 것은 이 public 폴더 안의 내용들뿐입니다.

  2. 관리해야 할 폴더와 파일

A. 소스 코드 저장소 (작업용)
블로그의 설정, 글 원본, 테마 등을 보관하는 곳입니다. PC를 옮기거나 설정을 바꿀 때 필요합니다.

  • 포함해야 할 것: _config.yml, package.json, source/, scaffolds/, themes/
  • 제외해야 할 것 (Git에서 무시): node_modules/, public/, .deploy_git/, db.json 등

B. 배포용 저장소 (GitHub Pages)
실제 웹사이트가 호스팅되는 곳입니다.

  • 포함되는 것: hexo generate 명령어로 생성된 public/ 폴더 안의 모든 파일들.
  • 특이사항: 직접 파일을 올리기보다는 Hexo의 자동 배포 도구를 사용하는 것이 일반적입니다.
  1. 배포를 위한 준비 단계 (설명만)

지금 당장 배포하지 않더라도, 다음의 과정이 필요하다는 점을 기억해 두세요.

① 배포 플러그인 설치
Hexo에서 GitHub로 자동 전송해주는 도구가 필요합니다. 보통 다음 명령어를 사용합니다.

② _config.yml 수정
파일 하단의 deploy: 섹션에 GitHub 저장소 주소를 입력해야 합니다.


③ 배포 명령어 순서
로컬에서 확인이 끝났다면 다음 세 단계를 거칩니다.

  1. 포스팅 md 문서 메타 태그
  • title: 포스트 제목
  • date: 작성 날짜 (YYYY-MM-DD HH:mm:ss)
  • updated: 수정 날짜
  • comments: 댓글 활성화 여부 (true/false)
  • tags: 태그 (배열 또는 단일 값)
  • categories: 카테고리 (배열 또는 단일 값, 계층 구조 지원)
  • permalink: 커스텀 URL
  • excerpt: 포스트 발췌문/요약
  • disableNunjucks: Nunjucks 태그 처리 비활성화 (true/false)
  • lang: 언어 설정 (예: ko, en)
  • published: 발행 여부 (false로 설정 시 draft와 동일)
  • layout: 레이아웃 선택 (post, page, draft 등)
  • cover: 커버 이미지 경로
  • thumbnail: 썸네일 이미지 경로
  • photos: 사진 갤러리 (배열)
  • link: 외부 링크
  • description: 메타 설명 (SEO용)
  • keywords: 키워드 (SEO용)
  • author: 작성자
  • top: 상단 고정 (테마에 따라 다름)
  • sticky: 고정 포스트 (숫자로 우선순위 지정 가능)
  • mathjax: MathJax 활성화 여부
  • toc: 목차 표시 여부
  • password: 비밀번호 보호 (테마 플러그인 필요)
  • categories:
    • [Sports, Baseball]
    • [Sports, Football]
    • [Life]

  1. 메타태그 주석처리.
    - ‘# ‘ 샾공백

  2. 스타일 변경 (내 스타일)
    - 백릿 3개 찍어서 소스코드 보는 부분에 대한 스타일에서, 좌우 여백 없이 가로를 꽉 채운다. 답답하다.
    - 이 부분을 좌우 마진을 사용하도록 수정하였다.
    - ./public/css/style.css

요약하자면:
우리는 source/ 폴더(글 원본)와 _config.yml(설정)을 잘 관리해야 하며, 배포 시에는 Hexo가 알아서 public/ 폴더의 결과물만 GitHub에 전송하도록 설정하게 됩니다.
